# 舰队数据分析

「舰队管理 → 舰队数据分析」在现有面板上提供三个标签：**舰船数据、心智分析、舰队科技分析**。不增加页面层级；路由 `/i/:instance/task/FleetAnalysis` 默认显示舰船数据，`tab=mind` 和 `tab=technology` 保留旧分析入口。

## 玩家维护的舰船表

舰船数据直接显示 SQLite 的已确认底账，每张卡一行。玩家可添加、删除、修改名称、舰船类型、等级、稀有度、原始稀有度、零散经验、核对标记和是否排除心智计算。内部序号区分同名副本；修改和采纳明确匹配的更新保留该序号。新增记录才分配新序号，不把两张同名卡合成一张。

`extra_exp` 是可空整数，留空表示经验未知，0 表示已知为零。当前扫描不读取经验，也不会用未知经验覆盖人工经验。舰名输入复用心智舰船目录的联想候选，选中后同时填写名称、舰船组 ID、显示稀有度和基础稀有度；组 ID 只读，无需玩家记忆。同名候选保留目录中的舰种或阵营后缀，改造、META、μ兵装、小型舰和 II 型保留各自名称。自由输入未匹配目录的名称会清除旧组 ID 并标为待核对，不猜测群组，也不沿用旧舰身份。

扫描身份转换统一输出底账支持的稀有度：科研分类 `PR/DR` 分别转为 `SSR/UR`，科技目录自身保留 `PR/DR` 展示。改造舰的 `rarity` 比基础档位高一级，最高为 `UR`；`base_rarity` 保留基础档位，心智费用不会跟随改造升档。扫描与人工编辑仍使用同一严格枚举，不因科研分类而放宽存储或接口校验。

表格支持搜索、筛选和每页 50 行。名称、舰船组 ID、等级、稀有度、基础稀有度、额外经验、核对标记、排除标记八列及卡片 ID 可点击表头切换升降序；先对全部筛选结果排序，再分页。等级与经验按数值排序，稀有度按 N、R、SR、SSR、UR 排序，空值始终置后，相同值以卡片 ID 稳定排序。新增舰船时清除筛选和排序并定位到新行，舰名、等级和经验在失焦或回车时提交，避免输入中重排。未保存草稿按实例保留，轮询和切换标签不覆盖草稿。底账版本改变后，过期草稿不能直接覆盖服务器，需要重新载入核对。保存只提交修改过的行和明确删除的内部序号。

## 读取结果由玩家采纳

主动扫描和读取本地旧 JSON **只产生待确认差异**，不自动改写舰船表、科技等级或人工记录。待确认区并列显示现有值与新读数，支持逐条采纳、逐条忽略、全部采纳和全部忽略。未处理的差异保存在 SQLite 中，重新载入仍可继续处理；仅保留最新一次读取，不保存批次历史。

同名副本先按可确认的相同属性作多重集合匹配；剩余读数只有唯一对应时才建议更新。存在多个可能对应记录时，必须由玩家选择现有内部序号或明确新增，不能直接全部采纳。一次审核不能将多张卡写入同一内部序号。

只在完整的 1–125 级扫描、到底、清空过滤、卡片数量吻合且无疑点时提出缺失删除建议；删除也需要玩家采纳。局部或不确定读取不删除未读到的底账记录。读取失败、取消和版本冲突均不提交更新。

心智计算与科技分析只读取已确认底账。即使存在新读取结果，分析也不提前使用未采纳值。科技人工状态和阵营等级仍可在科技列表中直接修改；已有人工状态优先，重新载入只读取数据库，不采纳候选。历史取得的科技成就不因删除舰船而撤销。

心智标签保留费用计算、试算、文件解析与截图识别预览；持久化修改统一在舰船数据表完成，不再保存单独的心智等级覆盖、额外清单或排除数据库。排除标记直接属于对应舰船行。

## 存储

每个实例仍使用 `config/fleet/<实例名>.sqlite3`，普通任务配置 JSON 只保存扫描设置。schema v3 使用类型化 SQL 列，不存舰船 JSON payload：

| 表 | 内容 |
| --- | --- |
| `ships` | 已确认舰船底账，逐卡、带内部序号和排除标记 |
| `technology` | 累计科技等级和玩家编辑的科技状态 |
| `nation_technology` | 玩家编辑的阵营等级 |
| `fleet_info` | 当前底账版本、时间、旧数据读取标记及待确认版本 |
| `pending_ships` | 最新读取中待处理的舰船差异 |
| `pending_technology` | 最新读取中待处理的科技差异 |
| `pending_nations` | 最新读取中待处理的阵营等级差异 |
| `pending_targets` | 同名卡片待确认差异可选的底账序号，处理后删除 |

pending 表仅是尚未采纳的更新区及同名卡片的候选对应关系，决定后删除对应候选，不是历史库。不存在 `mind_settings`、扫描批次、逐次证据表或旧 JSON 原文归档。

## 旧数据与边界

旧 `DockScan.Dock.Result`、心智 `Result/Analysis/FleetTechRecord` 和 `FleetTechScan.FleetTech.Record` 默认忽略。用户主动点击读取旧数据后，后端只读取当前实例在服务器本地的 JSON，转换为待确认差异，不上传、不接受任意路径、不清理原文件。旧心智修正转成普通舰船字段的建议更新；旧科技与阵营等级同样先等待选择。

每个实例仅允许成功读取旧数据一次，错误不会消耗机会。即使原 JSON 此后改变，也不会在后台读取。没有 SQLite 的实例默认空白，可人工录入或主动读取；旧试验版数据库不会自动清空。复制实例不复制舰船数据库，删除实例会将 JSON 与舰船库按同一时间戳归档到 `config/backup/`。

手动 `DockScan` 仅导航船坞、调整展示条件、滚动与读取卡片，不升级、突破、觉醒、退役、换船或战斗。分析页面和数据表操作不触发设备任务；扫描仅在玩家主动点击时运行，并沿用实例互斥与国服限制。

## 接口与验证

| 接口 | 行为 |
| --- | --- |
| `dock.report` | 已确认底账、底账版本和待确认差异 |
| `dock.patch` | 按内部序号修改、删除或新增底账行 |
| `dock.review` | 在底账与候选双版本校验下，采纳或忽略指定差异 |
| `dock.configure` | 保存下一次读取的等级范围 |
| `dock.importLegacy` | 显式读取本地旧 JSON，仅生成候选 |
| `mind.report` | 从已确认底账计算心智费用 |
| `mind.save` | 兼容错误提示，引导到舰船数据表，不写影子数据 |
| `fleetTech.report/patch` | 查看、编辑已确认科技状态 |

所有写接口沿用登录、实例隔离、演示只读和配置生命周期锁。自动验证使用临时配置、SQLite 和截图夹具，不操作真实游戏。核心用例为 `tests.test_fleet_ledger`、数据库与 API/扫描回归，以及 `mind-fleet-ledger.spec.ts` 浏览器测试。
