# 船坞数据分析

## 页面与边界

「舰队管理 → 数据分析」统一提供共享船坞数据、心智分析和舰船科技分析。路由为 `/i/:instance/task/FleetAnalysis`，`tab=mind` 或 `tab=technology` 选择分析。旧心智和科技路由兼容跳转，两个分析标签保留各自草稿。

打开页面只读取本地数据库和扫描设置，不调用设备或启动任务。用户点击「扫描船坞数据」时才执行手动 `DockScan`：回主界面清除隐藏搜索，进入船坞、重置筛选排序、回顶并逐页读取卡片。不觉醒、升级、突破、强化、退役、换船或战斗；遇到通用确认弹窗停止并保留旧快照。扫描仍遵循实例运行互斥，仅支持国服。

## 唯一扫描底账

`module/retire/dock_scan.py` 从原心智扫描提取页面稳定、三排行进、滚动配准、底部证明和有界复读，采用原科技群组身份目录。`MindCalculatorScan` 和 `FleetTechScan` 只保留为兼容入口，统一调用共享任务，工具菜单隐藏这些入口。

`config/fleet/<实例名>.sqlite3` 是按实例独立保存的 SQLite 舰船数据库，由 `module/runtime/fleet_database.py` 管理。任务配置 JSON 只保存扫描设置，不再存储舰船清单。`ships` 是类似电子表格的当前舰船表，每张物理卡片有一个数据库内部 ID；这是当前存储记录的 ID，不是游戏中的永久身份。使用有类型的列保存群组身份、舰名、等级、基础稀有度、待核对、来源和当前清单顺序。同名卡片和相同舰船的多个副本分别存在，不合并为一行；扫描行列位置仅用于识别过程，不作为持久字段或跨次人工校正的身份。可空的 `extra_exp` 列仅预留额外经验，当前不识别经验，扫描写入 NULL。费用在读取时计算，人工心智设置与科技进度独立保存。

最新扫描信息只有一条，保存范围、时间、底部与过滤证明、物理卡片数、OCR 船坞数量、完整性和版本摘要。扫描成功后替换当前舰船表和最新扫描信息，每张卡片分配新的记录 ID，不跨扫描匹配身份；累计科技成就保存在独立的类型化进度表中，不保存扫描批次、逐次历史证据或旧 JSON 归档。提交在 SQLite 事务中完成，重新检查最新底账版本，拒绝覆盖扫描期间替换的新版本；取消、失败和内存不足不提交。

默认范围为 **1–125**，可选择局部范围。仅范围为 1–125、确认到底、过滤清除、实际卡片数与船坞数量一致且无待核对条目，才允许根据未读到确认缺失。成功提交的局部扫描同样替换全部当前卡片行，不沿用上次扫描的范围外卡片；当前表只包含本次实际读取的结果，包括为证明早停而读到的范围外卡片，分析层按范围筛选。累计科技表中的已获得状态和最高自动等级继续保留，局部或不确定扫描不会降低这些成就。取消或失败的扫描不替换当前表。界面将已保存快照覆盖范围与下一次扫描配置分开显示。

数据库只有以下五张业务表：

| 表 | 保存内容 |
| --- | --- |
| `ships` | 当前扫描的逐卡行；同名副本分别保存 |
| `fleet_info` | 单条最新扫描信息、导入标记及设置元信息 |
| `technology` | 每个舰船类型的累计最高自动等级与人工科技字段 |
| `nation_technology` | 阵营科技等级 |
| `mind_settings` | 心智人工覆盖、删除及额外录入 |

例如 `ships` 的部分列可以是：

| id | group_type | name | level | rarity | base_rarity | extra_exp |
| --- | --- | --- | --- | --- | --- | --- |
| 41 | 10102 | 杜威 | 120 | R | R | NULL |
| 42 | 10102 | 杜威 | 100 | R | R | NULL |

这里的 `id` 仅标识存储记录，新扫描会分配新 ID；`group_type` 标识舰船类型，不区分游戏中的同型副本。`extra_exp = NULL` 表示经验未知或未采集，0 才表示已知额外经验为零，不能用 0 代替未知。当前扫描不采集经验，两行均写入 NULL。

## 分析与人工设置

`module/runtime/dock_data.py` 提供纯数据投影。心智投影按确认群组转换为原心智目录的限定名，避免把两种「天城」「加贺」混为同一艘；确认副本按基础身份取最高，待核对项分别保留。原费用规则与特殊船计费排除不变。

`module/runtime/mind_analysis.py` 将人工差异保存在数据库的独立心智设置中：按已确认群组保留排除、等级和基础稀有度覆盖、删除及额外录入。新扫描更新未人工覆盖的字段。待核对卡位的校正不跨扫描版本按行列套用，避免排序变化误改其他舰船。

科技从相同底账及累计自动证据生成本轮快照与历史进度。累计科技保留曾确认获得及历史最高等级：后来扫描只发现低级副本或完整扫描未再发现，也不撤回已有科技进度。本轮原始快照与心智清单仍反映当前扫描；人工明确的低等级或否定覆盖优先，恢复自动记录后再次使用历史证据。人工覆盖、等级切换端点和阵营等级保存在数据库的独立科技设置中，不复制扫描清单。重载时合并扫描证据与已有人工记录：扫描中未出现的人工舰船仍保留，新扫描等级不覆盖人工等级，明确设置的未获得、未满星和未到 120 级也继续有效。心智计费排除不会改变科技持有状态，科技人工等级也不会修改心智或原始读数。

## 旧配置与接口

旧配置中的 `DockScan.Dock.Result`、`MindCalculatorScan.MindCalculator.Result/Analysis/FleetTechRecord` 与 `FleetTechScan.FleetTech.Record` 默认全部忽略，不作为报告数据源，也不自动迁移。没有独立数据库的实例首次打开时舰船数据为空，可以重新扫描或选择显式导入。配置更新暂时保留这些旧数据字段，普通报告和分析保存不读取它们。

数据源区域提供「导入旧舰船数据」按钮。用户主动点击后，后端只读取当前实例在服务器上的配置 JSON，不上传文件，也不读取其他实例。每个实例仅允许成功导入一次，从上述五处旧数据选出一份当前舰船清单，合并累计科技成就、心智设置、科技人工覆盖和阵营等级，转换到 SQLite；不保留旧批次和原始 JSON。已有 SQLite 人工字段（包括否定、显式空值和 0）优先，仅补入缺失字段。数据库区分「没有人工字段」与「人工字段明确为 NULL」；旧数据也保留这种区别，不用旧值填补已有的显式空值。已有扫描保持当前原始读数，旧自动正向证据合入累计历史；没有现有扫描时优先使用旧共享船坞快照，否则选择有可信时间的较新旧扫描。旧心智或科技清单不冒充完整船坞。

格式错误、没有可用旧数据或版本冲突不会消耗导入机会。成功导入后显示已导入，并清除配置 JSON 中已导入的旧舰船数据字段；若配置清理失败，数据库导入仍有效，留下的字段继续忽略。此后舰船数据读写只使用 SQLite，恢复人工自动记录不会重置导入标记。显式空扫描是有效结果，不能复活旧清单。


扫描范围仍保存在实例配置的 `DockScan.Dock.MinLevel/MaxLevel`；扫描清单、心智人工设置、科技人工设置和阵营等级独立保存在数据库。复制或备份配置 JSON 不会包含舰船数据。备份或恢复舰船数据前先停止应用，再复制对应的 `config/fleet/<实例名>.sqlite3`；恢复时保持实例名对应。复制实例仅复制任务设置，不复制舰船数据库；删除实例时，配置 JSON 与对应 SQLite 文件使用同一时间戳归档到 `config/backup/`，数据库备份名为 `<实例名>-<时间戳>.fleet.sqlite3`。

| 接口 | 行为 |
| --- | --- |
| `dock.report` | 返回源、时间、当前逐卡清单、版本、完整性、待核对数和范围 |
| `dock.configure` | 仅保存下一次扫描等级范围，不改已有快照或启动游戏 |
| `tasks.run(DockScan)` | 使用既有任务运行互斥，显式启动共享扫描 |
| `mind.report/save` | 派生心智报告，人工保存仅写分析差异 |
| `fleetTech.report/patch` | 派生科技报告，人工编辑仅写科技设置 |
| `dock.importLegacy` | 用户主动将当前实例本地旧舰船数据一次性导入 SQLite；已有数据库字段优先 |
| `fleetTech.syncMind` | 旧客户端兼容；始终为无副作用的报告读取，不导入心智清单 |

API、服务与生成契约沿用现有登录、演示只读和实例隔离边界。报告与人工保存使用版本校验，过期编辑报冲突，不自动覆盖扫描或其他页面草稿。

共享源、数据库和服务回归为 `tests.test_dock_data`、`tests.test_fleet_database`、`tests.test_dock_service`；原截图、位移、排序、底部、失败保留与并发测试继续覆盖抽取后的扫描器。前端 `FleetAnalysis.test.tsx` 及 mock 浏览器验证统一入口、旧路由与查看不启动任务。所有自动验证使用隔离数据或已有截图，不连接真实游戏。
